CSS layout library

Responder

Row and column pages, with the colors, type, and spacing kept in one file. Plain CSS. No Sass, no build, no JavaScript.

Written by Larry J. Lane. This manual replaces respondermanual.html.

One theme file

Change css/themes/default.css and every component follows. The switch in the header loads the dark theme with a radio button.

Include what you need

Link responder.css for everything, or link the theme plus the few component files a page uses.

Same grid idea

.row and .column-50 still add up to a full line. Columns stack on a narrow screen.

Include the CSS

The published site is larryjoelane.github.io/responder. Paths below are from your own project, after you copy the css folder.

Everything, default theme

<link rel="stylesheet" href="css/responder.css">

responder.css is a list of @import rules, not a file that was concatenated by a build. One link tag pulls in the theme and every component. The browser then requests each file. That stays in sync with the modules, and it costs extra requests, which HTTP/2 and HTTP/3 handle well. A single physical file would need a build, or a second copy that can drift.

Only the pieces you need

Link the theme first so it can set the cascade layer order. Then base, then any components. Utilities last is a good habit; the layer order already puts them above components.

<link rel="stylesheet" href="css/themes/default.css">
<link rel="stylesheet" href="css/base.css">
<link rel="stylesheet" href="css/grid.css">
<link rel="stylesheet" href="css/layout.css">
<link rel="stylesheet" href="css/utilities.css">

Theme

Colors, type, spacing, radii, shadows, content width, header and footer height, column gap, and the breakpoint notes all live in css/themes/default.css. Components never hard-code those values. They read var(--responder-color-accent) and the other properties.

The header control on this page is two radio buttons. themes/dark.css applies its properties while #theme-dark is checked, using :root:has(#theme-dark:checked). Reloading the page returns to the default, because nothing stores the choice. That would take JavaScript.

To make a whole site dark without a switcher, link the dark bundle instead of the default one. This page does that.

<link rel="stylesheet" href="css/responder-dark.css">

A switcher on your own site is the default bundle, plus the dark theme file, plus a radio whose id is exactly theme-dark:

<link rel="stylesheet" href="css/responder.css">
<link rel="stylesheet" href="css/themes/dark.css">

<input type="radio" name="theme" id="theme-default" checked>
<label for="theme-default">Default</label>
<input type="radio" name="theme" id="theme-dark">
<label for="theme-dark">Dark</label>

Loaded by itself, dark.css themes the page. Loaded after the default theme, it does not win until that radio is checked. The default rules use :root. The dark rules use :where(:root), which loses on purpose, and the :has() rule, which wins when the radio is on.

The old extend-responder.css file was the theme: Georgia, a green page, a black header and footer, teal hovers, and white columns. Those are tokens now. The page background is a calmer sage than #99ff99. Set --responder-color-bg back to #99ff99 if you want the original green. White column fills are the .card class, not something every column gets.

Grid

Put column classes on the direct children of .row. Percentages are the same set as before: steps of 5 from 5 to 100, plus 1, 8 (one twelfth), 12 (one eighth), 33 (one third), and 66 (two thirds). .column-50 is the name to write. .column50 still works.

The gap between columns is --responder-column-gap. Below 480px the columns become full width, unless the row has .row-fixed.

Layout

A page is a column: header, growing main area, footer. The footer sits at the bottom of the viewport when the page is short. Use the classes, or the old ids #header, #wrap, and #footer.

.container sets the content measure to --responder-content-width. #wrap itself stays full width, as it used to. .center-vertical centers its contents, and centers itself in the header or footer.

Utilities

.hide removes an element from the layout and from the accessibility tree. The show and hide classes follow the viewport width. Resize the window to see which boxes remain. The note under each box stays visible.

small-hide

Hidden at 480px and below.

medium-hide

Hidden from 481px to 768px.

large-hide

Hidden from 769px to 992px.

extra-large-hide

Hidden from 993px up.

small-show

Shown only at 480px and below. On a wider window this box is gone.

extra-large-show

Shown only from 993px up.

Markup 
<div class="small-hide">Hidden on a phone.</div>
<div class="small-show">Shown only on a phone.</div>
<p class="hide">Gone at every size.</p>
<p class="text-center">Centered text.</p>

<div class="stack">
  <p>First</p>
  <p>Second, spaced by the stack.</p>
</div>

.visually-hidden hides something visually and leaves it available to assistive technology. The theme control's legend uses it. .text-center and .text-end set alignment. .stack is a vertical list with --responder-space-4 between the children.

Images

.responsive-image fills the column and keeps its ratio.

Accordion

The old stylesheet mentioned #accordion and never built one. This one is details and summary. The shared name keeps a single panel open.

What is a row?

A row lays out its direct children on one line until the window is 480px or narrower. Then they stack.

Where do colors live?

In the theme file, as custom properties. Components only refer to those names.

Does this need JavaScript?

No. Opening and closing is built into the details element.

Markup 
<div class="accordion">
  <details name="topics" open>
    <summary>What is a row?</summary>
    <div class="accordion-panel">
      <p>A row lays out its direct children.</p>
    </div>
  </details>
</div>

Tabs

Each tab is a radio button, its label, and a panel, in that order. Radios in one set share a name. Arrow keys move between them the way they do in any radio group.

column-50 and column-50. Or column-33 and column-66. The class number is the percentage, except for the fractional columns 8, 12, 33, and 66.

Edit one file of custom properties. Link responder-dark.css, or offer both files and a radio with id theme-dark.

Skip the bundle and link themes/default.css, base.css, and the components that page actually uses.

Markup 
<div class="tabs">
  <input type="radio" name="notes" id="tab-columns" checked>
  <label for="tab-columns">Columns</label>
  <div class="tabs-panel"><p>Column copy.</p></div>

  <input type="radio" name="notes" id="tab-theme">
  <label for="tab-theme">Theme</label>
  <div class="tabs-panel"><p>Theme copy.</p></div>
</div>

Popover

A button with popovertarget toggles a panel that has the popover attribute. The panel light-dismisses. No JavaScript. Browsers without popover support show the panel in place.

Fractional columns

column-8 is one twelfth, column-12 is one eighth, column-33 is one third, and column-66 is two thirds.

Markup 
<button class="button" type="button" popovertarget="widths">Column widths</button>
<div id="widths" class="popover" popover>
  <p>column-33 is one third of the row.</p>
</div>

Notices

The theme file is the only place to change the accent color.

Columns that add up to 100 stay on one line above 480px.

Media queries repeat the breakpoint pixels. A custom property cannot drive a media query.

Do not combine .hide with a show class. .hide wins.

Markup 
<p class="notice">A note.</p>
<p class="notice notice-success">It worked.</p>
<p class="notice notice-warning">Read this.</p>
<p class="notice notice-danger">Something failed.</p>

Breakpoints

The theme file records the three widths. Stylesheets repeat the numbers, because var() is not valid inside @media, and @custom-media is not supported in browsers.

  • grid.css stacks columns at 480px.
  • nav.css swaps header navigation at 768px.
  • utilities.css hides and shows at 480, 768, and 992.

Change a width in the theme token and in those files together. The ranges do not overlap: 480 belongs to small, 768 belongs to medium, 992 belongs to large.

Changes from the 2014 library

Sass, gulp, gulpfile.js, and src/sass are gone. What used to live in extend-responder.css is the theme file now. The manual is this page.

  • Write .column-50. .column50 still matches. The old manual's id="column100" never matched the CSS; use a class.
  • Only the direct children of a row are columns. Nested divs are not floated.
  • Columns are not automatically white. Add .card.
  • Below 480px, columns stack. The separate 320px query did the same thing and was removed. .row-fixed opts out.
  • Header and footer heights are tokens. The sticky footer is flexbox, not a negative margin. The body font no longer shrinks between 768px and 992px.
  • .hide and the breakpoint classes use display: none. .small-show is visible only on a small screen. Medium, large, and extra-large show classes are new.
  • In the header, horizontal nav and the mobile menu no longer both disappear at exactly 768px. The swap is at 768px.
  • Nav hover no longer uppercases the link.
  • The root responder.css imports css/responder.css.

Left out, because it needs JavaScript

  • Modal dialogs. dialog.showModal(), a focus trap, and a close control that removes the open state need script. Popover covers a light-dismiss panel.
  • Carousels, drag, and anything on a timer.
  • Copy buttons. Code samples are selectable text.
  • Remembering the theme across reloads. Swap responder-dark.css in for a permanent dark site.
  • A touch menu that is not details or popover. The legacy hover menu is still there, and it is not the one to use on a phone.
